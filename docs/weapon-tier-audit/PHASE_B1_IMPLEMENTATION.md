## 1. Prisma schema changes

`backend/prisma/schema.prisma` (additive only):

- `Weapon.tierRanks WeaponTierRank[]` relation added. `Weapon.tier`, `Weapon.role`, IDs, detail fields and `TierRank` untouched.
- Enums: `WeaponTierRole`, `WeaponRankTier`, `WeaponTierReviewStatus`, `WeaponTierDerivation`, `WeaponRefinementContext`, `WeaponVersionStatus`, `WeaponConfidence`.
- `WeaponTierRank`: weapon/type/role/tier, refinement **context + level**, `versionKey` + nullable `gameVersion` + status, explanation, evidence, rubric, confidence, review metadata, provenance, `publishRightsVerified`, `approvedBy`, timestamps.
- `WeaponTierAudit`: action, server-side actor, JSON changes, timestamp.
- Unique key `@@unique([weaponId, role, versionKey, refinementContext])`. Every key column is non-null, so PostgreSQL never relies on NULL equality. `SOURCE_MISSING`/`UNSPECIFIED` are enum values, not NULLs.

Note: `prisma format` was run to validate the additions; it realigned whitespace across the file. A whitespace-ignored diff shows only the pre-existing Character Tier / Multi-Build changes plus the weapon additions — no semantics were lost or overwritten.

## 6. GraphQL added

`backend/src/graphql/modules/weaponTierRanking/` — schema, service, resolvers and five test files.

- Types: `WeaponTierRank`, `WeaponTierAudit`, 7 enums, `WeaponTierRankInput`.
- Queries: `weaponTierRanks` (public), `adminWeaponTierRanks` (admin), `weaponTierAuditLog` (admin), plus `Weapon.tierRanks`.
- Mutations: `upsertWeaponTierRank`, `approveWeaponTierRank`, `rejectWeaponTierRank`.

- No ranking value is hardcoded in a resolver; all tiers come from validated input.

## 7. Admin approval protection

- Every admin read/write calls `assertAdmin` from server-side context (`x-admin-key` → `ADMIN_PASSWORD`).
- `approve` rejects `SOURCE_DERIVED`, unexplained, rights-unverified and already-approved rows; records `approvedBy` from context, never from input.
- `SOURCE_DERIVED` rows cannot be relabelled `INDEPENDENT`. `APPROVED` rows are immutable.
- Compare-and-swap on `updatedAt` + previous `reviewStatus`: a stale edit or concurrent review fails with `CONCURRENT_MODIFICATION`.
- Every create/update/approve/reject writes an audit record with the acting admin.

## 8. Public query protection

`weaponTierRanks`, `Weapon.tierRanks` and the DataLoader all hard-filter `reviewStatus=APPROVED`, `derivation=INDEPENDENT`, `publishRightsVerified=true`. Public SDL has no review-status or derivation argument. There is no fallback from rarity, base ATK or popularity. With 0 approved rows both queries return `[]`.
